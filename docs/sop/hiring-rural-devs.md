# Growth Teams — Hiring Rural Developers SOP

---

## Philosophy

We hire for attitude, accountability, and learning velocity. Technical skills can be taught in 3–6 months. The desire to improve, the honesty to admit mistakes, and the discipline to deliver on time — these cannot be trained easily.

We are intentionally building in a village. We pay above local market rates. We create a genuine career path. This is not charity — it is strategy. Loyal, well-trained local developers who feel ownership over their work produce better software than mercenary hires in any city.

---

## Who We Are Looking For

### Non-Negotiable Traits
- **Honest:** Will tell you when they do not know something instead of pretending
- **Curious:** Reads about code outside of work hours, even a little
- **Accountable:** When something goes wrong, first reaction is to fix it, not to blame
- **Communicates:** Can write a clear message explaining what they are working on

### Technical Starting Point (Minimum Bar)
- Can write basic code in any language (Python, JavaScript, Dart, Java)
- Understands functions, loops, and data structures
- Has built *something* — even a simple project, even if unfinished
- Familiar with how the internet works (HTTP, request/response)

### We Do NOT Require:
- Computer Science degree
- Previous company experience
- Specific tech stack knowledge (we train this)

## Hiring Process (3 Stages)

### Stage 1: Async Technical Task (No interview yet)
**Goal:** See how they think, not whether they can pass a whiteboard interview.

**Send this task via email:**
```
Thank you for reaching out. Here is a short task to understand how you think.

Task: Build a simple to-do list app in any language/framework you prefer.
Requirements:
- Add a task
- Mark a task as complete
- Delete a task
- Tasks should persist (file, database, or local storage — your choice)

Send us:
- A link to your code (GitHub, GitLab, or a zip file)
- A short note explaining: what you built, what you found difficult, and what you would do differently if you had more time

Deadline: 5 days from now.
There is no perfect answer. We are looking at how you approach problems.
```

**What you are evaluating:**
- Did they submit on time?
- Is the code readable (even if basic)?
- Did they explain their thinking clearly in the note?
- Did they acknowledge what they do not know?

**Red flags:**
- Copied code without understanding it (ask follow-up questions)
- No submission without explanation
- Defensive or dismissive in their note

### Stage 2: 30-Minute Video Call
**Goal:** Assess communication, curiosity, and cultural fit.

**Questions to ask:**
1. Walk me through what you built for the task.
2. What was the hardest part? How did you figure it out?
3. What do you know about Flutter / Python / React? (whichever is relevant)
4. What did you build most recently (outside this task)?
5. Describe a time you got something wrong. What happened?
6. What do you want to learn in the next year?
7. Do you have a reliable laptop and internet connection at home?

**What you are listening for:**
- Honesty (especially Q5)
- Curiosity (Q4, Q6)
- Clear communication (not vocabulary — clarity)
- Self-awareness

**Green flags:** Says "I don't know but I would look it up like this…"  
**Red flags:** Over-claims skills, deflects blame in Q5, cannot explain their own code

### Stage 3: Paid Trial Project (2 weeks)
**Pay:** 50% of proposed salary for 2 weeks.  
**Goal:** See how they work in a real environment before committing.

**What to assign:**
- A small, isolated real task (not a toy project)
- Something with clear acceptance criteria
- Something that involves Git, code review, and documentation

**Evaluate:**
- Did they ask the right questions before starting?
- Did they deliver by the agreed date?
- How was their code quality (not perfection — reasonableness)?
- How did they handle feedback?
- Did they communicate proactively when blocked?

## Offer & Compensation

### Starting Salary (Junior, Year 1)
- **Target:** 30–50% above local market rate for software jobs in your district
- **Research:** Check local job boards, ask at engineering colleges
- **Example:** If local juniors earn ₹12,000–₹15,000/month, offer ₹20,000–₹25,000
- **Include:** Training, mentorship, and real project exposure as part of the value

### Progression Path
| Level | Milestone | Salary Increase |
|-------|-----------|----------------|
| Trainee (Month 1–3) | Completes training programme | Base |
| Junior Developer (Month 3–12) | Delivers first sprint independently | +15–20% |
| Mid Developer (Year 1–2) | Leads feature independently, reviews PRs | +25–35% |
| Senior Developer (Year 2–4) | Owns a project, mentors juniors | +40–60% |
| Lead Developer (Year 4+) | Manages a team, owns client relationship | Negotiated |

## 3-Month Training Programme

### Month 1: Foundations
- Week 1–2: Git, GitHub, pull requests (hands-on)
- Week 3: How the web works (HTTP, APIs, REST)
- Week 4: Command line, environment setup, SSH basics

### Month 2: Core Stack
- Week 5–6: Flutter basics (if mobile) OR Python/FastAPI (if backend) OR React (if frontend)
- Week 7: Database basics (PostgreSQL, SQL queries, migrations)
- Week 8: Authentication (JWT, sessions, roles)

### Month 3: Real Work
- Week 9–10: Contribute to an active internal project (with code review)
- Week 11–12: Complete one isolated sprint task independently

**Resources (all free):**
- Flutter: flutter.dev official docs + Angela Yu Udemy course
- Python: FastAPI docs + testdriven.io tutorials
- React: reactjs.org official docs + Fireship YouTube
- Git: Pro Git book (free online)
- Databases: PostgreSQL Tutorial (postgresqltutorial.com)

## Probation Period (3 Months)

During probation:
- Weekly 1-on-1 with founder (30 min)
- Written feedback at Week 4, Week 8, Week 12
- Clear, written expectations shared at the start

**If probation is not working:**
- Address issues in writing at the Week 4 or Week 8 check-in
- Give specific, actionable feedback with a 2-week improvement window
- If no improvement, end the engagement at the end of probation with 2 weeks' notice and any owed pay

**Never:** Let probation drift past 3 months without a clear decision.

## Work Setup Requirements

Before anyone starts full-time:
- Laptop with minimum: 8GB RAM, SSD, working webcam
- Internet: At least 10Mbps stable (they must test this and confirm)
- Power backup: UPS or inverter (power cuts are real)
- Quiet space for calls

**If they cannot afford a laptop:**  
Consider a laptop loan (deducted from salary over 12 months) for candidates who pass all 3 hiring stages. Document this as a written agreement.

## Company Culture (Village Edition)

We are building something unusual: a world-class software company in a rural area. That is the narrative. Lean into it.

- Celebrate every international client win with the team
- Share client appreciation messages publicly (within the team)
- When we travel to a city for any reason, bring the team
- Create a physical notice board in the office (even a corner of a room) that shows: active clients, countries served, projects delivered
- Treat every team member as a co-owner of the company's reputation

People work harder for a mission they believe in than for a salary alone.
